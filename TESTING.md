# Testing tamash-selenium

Operating manual for verifying this package — for a human or an agent picking up a feature, a fix,
or a review. It captures what isn't derivable from the code: how to set up a real test, traps that
look like package bugs but aren't, and the checklist a change must pass before it's trustworthy.

See [`RELEASE-TESTING.md`](RELEASE-TESTING.md) for the current honest coverage matrix and
[`TEST-PARITY-ROADMAP.md`](TEST-PARITY-ROADMAP.md) for what's still being built out.

## The core rule

**Verify for real. Don't trust static analysis or "it should work" reasoning.**

Unit tests catch regressions in deterministic code (parsing, source rewriting, log I/O). They
cannot tell you whether a locator strategy resolves against a live DOM, or whether a provider's
response shape is still what we assume. Both layers are required; neither substitutes for the
other. Anything touching a live `WebDriver`, a provider call, or `apply-heals` rewriting real
source needs a real end-to-end run before it's done — not just a green build and unit suite.

## The three layers

### 1. Unit — fast, deterministic, no browser, no AI

```sh
mvn test
```

Runs everything **except** the browser and real-AI classes (surefire `<excludes>` in `pom.xml`).
~75 tests, a few seconds. Covers:

- `SourceLocationsTest` — `findAssignmentEquals` (incl. the `=`-inside-a-string regression),
  `decodeVariableName` (prefix/suffix styles, acronym boundaries, `imgur`≠`img` false-positive
  guard, meaningless-word guard), assertion/negative-line detection, locator-token extraction.
- `DurableLocatorTest` — `parseAriaAiTree` against a captured `DomSnapshot` fixture,
  `findRuleBasedMatch` (incl. the decorative-duplicate-label case and the token-set fallback),
  attribute stacking, `toBy`, `looksAutoGenerated`, `inferRoleFromAction`.
- `HealCacheTest` — the positive (locator+page, run lifetime) / negative (DOM-fingerprint, 3s
  TTL) two-tier cache, `failCount` peek-without-increment, `everHealed`, `clear()`.
- `HealLogTest` — `parseSourceLocation`, append/read round-trip (incl. `newLocator` / `newFindBy`
  / `declarationLocation`), sharded-dir merge, cache lookup.
- `ApplyHealsTest` — the paren/string-aware scanner: inline `By.x("…")`, `@FindBy(...)`, the
  `By field = By.x("…")` declaration line, and the `//`-comment skip.
- `PromptTest` — every `parseSuggestion` strategy shape, markdown-fenced JSON, missing-field
  rejection, `role`→css/xpath fold, snapshot truncation at `MAX_SNAPSHOT_CHARS`, the
  Selenium-flavoured system prompts, `parseActionTacticSuggestion` (all five wire values),
  OpenAI-shape usage extraction.
- `TamashRuleBasedProviderTest` — `parseDescriptionForMatch` (phrase + type hint, generic-suffix
  strip, empty guards), `suggestSelector` (resolve + every decline path), `suggestActionTactic`
  always `NONE`.
- `HttpRetryTest` — `Http.postJson`'s retry policy against a local `com.sun.net.httpserver` stub:
  `Retry-After` header (short → retry, long → fail fast), Gemini `retryDelay` body field, bare
  429 fails fast, 5xx one-retry-then-give-up.
- `ReportRendererTest` — a synthetic report → HTML: summary stats, heal note + token cost, HTML
  escaping, empty-steps placeholder, unrecovered-failure DOM-snapshot block.

### 2. Rule-based browser — real Chrome, no network

```sh
mvn test -Pbrowser -DHEADLESS=true
```

The `browser` profile runs the layer-1 tests **plus** every healing test that needs a real
browser, all against the zero-token `tamash` provider and `data:` pages (SampleTest and
AiHealingE2ETest stay out — they need an external resource). ~110 tests, ~2 min. Notable classes:

- `PatternsHealingTest` — the gauntlet: fluent Page Object `By` fields, `Select`, `Actions` API,
  **stale-element re-heal**, `@FindBy` + `AjaxElementLocatorFactory`, nested `container.findElement`,
  parameterized cache reuse, 3 broken locators in one test, `FluentWait`, wait-then-act,
  `findElements` (plural) **not** healed.
- `HealingDisabledTest` — `HEALER_ENABLED=false`: a broken locator throws `NoSuchElementException`
  exactly like vanilla, no `SelfHealingReport` token usage; a working locator is unaffected.
- `SelectHealingTest` — a broken `<select>` locator heals; `Select` operations then run on the
  real element. (Selenium's `Select` is a client-side utility, so this surface is smaller than
  Playwright's `selectOption`.)
- `IframeHealingTest` — a broken locator inside a `srcdoc` `<iframe>`; `switchTo().frame` is
  stateful so the healer's snapshot runs in the frame document; `defaultContent()` after.
- `ReplayArgForwardingTest` — a stale-then-replayed `sendKeys("A","B","C")` must forward every
  arg; a replayed `getDomAttribute("name")` must forward the attribute name.
- `GetDurableTest` — `Bindings.getDurable` resolves a brittle positional XPath to a durable `By`,
  is stable across repeated calls (no static-cache drift), throws on a non-resolving locator.
- `ReportCacheHonestyTest` — every reported/cached selector independently resolves to the intended
  element.
- `WaitHealingTest` — heals inside `WebDriverWait`/`FluentWait` with the polls kept to one heal;
  an element that never appears times out and is **not** "healed".
- `AssertionHealingTest` — `HEALER_ASSERTIONS=heal|warn|strict`; assert-absent never healed.

### 3. Real AI — real Chrome, real provider

```sh
# no-op unless a real provider is selected
mvn test -Dtest=AiHealingE2ETest -DHEALER_PROVIDER=anthropic -DANTHROPIC_MODEL=claude-haiku-4-5
mvn test -Dtest=AiHealingE2ETest -DHEALER_PROVIDER=openai   -DOPENAI_MODEL=gpt-4o-mini
mvn test -Dtest=AiHealingE2ETest -DHEALER_PROVIDER=gemini   -DGEMINI_MODEL=gemini-flash-lite-latest
```

`AiHealingE2ETest` heals three broken locators (wrong `name`, wrong `#id`, wrong button text) via
a live provider and asserts each heal came from that provider with a `By.…` suggestion. It
`assumeTrue`s a real provider, so it's silently skipped under plain `mvn test`.

`SampleTest` is the other real-AI class — a heal against a live hosted site; needs a provider key
and network.

Also run the CLI once against a real provider:

```sh
mvn exec:java -Dexec.args="doctor"     # provider connectivity + config checks
```

## Setting up a real test

### `.env` and keys

Config precedence is **OS env var → `-D` system property → `.env`**. `.env` at the repo root holds
the real keys and is gitignored.

- **Never** print, echo, or commit a real API key. When you must change `.env` for a test:
  `cp .env .env.backup-<label>` first, edit only the value needed with an editor (not a bash
  one-liner that echoes it), and restore (`cp .env.backup-<label> .env && rm …`) as the **last**
  step of the session, even if the test failed partway.
- Confirm success by behaviour (a `HEALED [provider=…]` line, token counts), never by echoing the
  credential.

### Provider models

- `anthropic` and `openai` have **no default model** — set `ANTHROPIC_MODEL` / `OPENAI_MODEL` or
  the provider silently doesn't initialise (`stage=no_provider`). `.env` doesn't set them; pass
  `-D…_MODEL=` or add them to `.env`.
- Use a **`-flash-lite`** Gemini model. A full `-flash` model thinks by default and takes 15–35 s
  for a 5k-token lookup — it times out. `gemini-flash-lite-latest` returns in ~2 s. tamash sends
  `reasoning_effort: low` on the Gemini surface regardless; `GEMINI_THINKING=on` restores the
  model default.

### The heal log is a cross-run cache — clear it

`.tamash-selenium/heals.jsonl` records every heal and is **reused as a cache on the next run**,
keyed by `locator + pageKey`, independent of provider. A second run of an AI test will be served
from it (`provider=cache`) and make no AI call — which silently defeats any "a real call happened"
assertion. `AiHealingE2ETest` deletes the file in `@BeforeAll` for this reason. Do the same in any
new AI test, or `rm .tamash-selenium/heals.jsonl` between runs.

`ProviderFactory` reads `HEALER_PROVIDER` **once** and caches the provider. Set it before the JVM
starts, or call `ProviderFactory.resetCache()` after `System.setProperty(...)` (the browser tests
do this in `@BeforeAll`).

### Writing a fixture

Prefer a `data:text/html,` page over a live site for anything not specifically testing the real
hosted app. For the **rule-based `tamash` provider**, the decoded description must resemble
on-page text — it matches literally, tolerating only reordering and stopwords. Two traps:

- **A nested assignment steals the variable name.** `Select x = new Select(driver.findElement(by))`
  makes `SourceLocations` decode the *outer* variable (`x`), not `by`. Name the outer variable
  after the field, or don't nest the `findElement`.
- **id beats name in the derivation ladder.** A broken locator for an element with both a real
  `id` and `name` heals to `By.id(...)`. Assert on "resolves to the right element", not on a
  specific strategy, unless the element deliberately has only one.

An AI provider tolerates paraphrase and needs neither.

### `MAX_SNAPSHOT_CHARS`

16000 (`healer/providers/Prompt.java`). The snapshot is truncated past that with `... (truncated)`
appended. There is no vision fallback in tamash-selenium, so a target truncated out of the
snapshot simply doesn't heal — don't use truncation as a test lever the way the Playwright package
does for its vision path.

## `apply-heals` round-trip

1. Run a browser or AI test so a heal is recorded in `.tamash-selenium/heals.jsonl`.
2. `mvn exec:java -Dexec.args="apply-heals --dry-run"` — check the `By.…` / `@FindBy` rewrite preview.
3. `mvn exec:java -Dexec.args="apply-heals --yes"` — rewrites the `.java` source, writes a
   verify script.
4. `sh .tamash-selenium/verify-heals.sh` — re-runs the affected test(s) with `HEALER_ENABLED=false`.
   **A pass is the actual proof a "durable" heal is durable** — one that only works with healing on
   hasn't been fixed.
5. `git diff` and revert — the point is to verify the mechanism, not keep the edit. Check
   `git status` first to confirm the file was clean.

The full round-trip is proven two ways: `ApplyHealsTest` unit-covers the rewrite + affected-test
computation for every locator shape, and the sample repo's CI `apply-heals` job runs
heal → `apply-heals --yes` → `verify-heals` against the live app on every push.

## HTML step report

```sh
mvn test -Pbrowser -Dtest=TamashRuleBasedHealingTest -DTAMASH_REPORT=target/tamash-report.html
```

Open it: a healed step shows `healed via <provider> — recovered as By.id("username")` with token
cost; an unrecovered failure shows a collapsible DOM snapshot.

## End-to-end checklist for a new/changed healing feature

Work through this in order. Don't skip a step because a change "looks small".

1. `mvn -DskipTests package` — clean compile.
2. `mvn test` — full unit suite, zero regressions (check the count didn't drop).
3. `mvn test -Pbrowser -DHEADLESS=true` — rule-based browser suite green.
4. Build a `data:` fixture that reproduces the exact trigger for the new code path.
5. Run it against a **real** provider (`-Dtest=… -DHEALER_PROVIDER=… -D…_MODEL=…`). Confirm the
   console line shows the expected `provider`, `actionRecovery` flag, `suggested` `By.…` shape.
6. If the heal should be `apply-heals`-eligible: check `.tamash-selenium/heals.jsonl` for the
   expected `newLocator` / `newFindBy`.
7. `apply-heals --yes` → `verify-heals.sh` — prove durability with healing off.
8. Run step 5 once more — a single AI run is one data point, not proof. Note any variance.
9. Clean up unconditionally: `rm -rf .tamash-selenium target/tamash-report.html`, restore `.env`
   / any `-D` fixtures, delete throwaway test classes, `git status` before committing.

## Gotchas

- The lifecycle pins Selenium's implicit wait to **0** so a broken `findElement` surfaces
  immediately. Healing runs on a direct `driver.findElement(broken)` **and** inside
  `WebDriverWait` / `FluentWait` (first few polls deferred as "still loading", then it heals).
- `findElements` (plural) is **never** healed — a broken plural locator returns `[]`.
- `apply-heals` rewrites an inline `By.x("…")`, an `@FindBy(...)`, or a `By field = By.x("…")`
  declaration line. Anything else is reported *skipped* — apply from `heals.jsonl` by hand.
- `.tamash-selenium/` is gitignored and accumulates across runs — delete it between unrelated
  sessions.
- Non-Chrome browsers (`TAMASH_BROWSER=firefox|edge|safari`) are supported by the lifecycle but
  **out of scope for the test suite** — Chrome is the covered configuration. The lifecycle's
  browser branches are exercised by hand when touched.

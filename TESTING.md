# Testing tamash-selenium

Operating manual for verifying this package.

## The core rule

**Verify for real. Don't trust static analysis or "it should work" reasoning.** Unit tests catch
regressions in deterministic code (parsing, source rewriting, log I/O); they cannot tell you
whether a locator strategy resolves against a live DOM or whether a provider's response shape is
still right. Anything touching a live `WebDriver`, a provider call, or `apply-heals` rewriting real
source needs a real end-to-end run before it's done.

## 1. Unit tests — fast, deterministic, no browser, no AI

```sh
mvn test
```

The browser / real-AI tests are excluded from the default run (surefire `<excludes>`). This runs:

- `SourceLocationsTest` — `findAssignmentEquals` (incl. the `=`-inside-a-string regression) and
  `decodeVariableName` (prefix/suffix styles, acronym boundaries, false-positive guards).
- `DurableLocatorTest` — `parseAriaAiTree` against a captured snapshot, `findRuleBasedMatch`
  (incl. the decorative-duplicate-label case), `generateReplacementCall` (Selenium `By.…` output),
  `extractScopedSnapshot`, `toBy`, `looksAutoGenerated`, `inferRoleFromAction`.
- `HealLogTest` — `parseSourceLocation`, append/read round-trip (incl. the rendered
  `newLocator` / `newFindBy`), sharded-dir merge, cache lookup, archive + clear.
- `HealCacheTest` — the positive (locator+page) / negative (DOM-fingerprint, TTL) two-tier cache
  and `clear()`.
- `ApplyHealsTest` — the paren/string-aware call scanner and `planFixes` rewriting real Java
  `By.…` source.
- `PromptTest` — the provider request/response parsing (`parseSuggestion`, lenient JSON).

## 2. Offline end-to-end — real browser, no network

```sh
mvn test -Dtest=TamashRuleBasedHealingTest -DHEALER_PROVIDER=tamash
```

A `data:` page, the `tamash` rule-based provider (zero tokens), and a deliberately-broken locator.
A pass proves the whole runtime path: proxy bindings → source-location + variable-name decode →
`DomSnapshot` → `findRuleBasedMatch` → `ref` resolution → `deriveSuggestionFromElement` → reflected
replay. Watch for a
`[self-healer] … -> HEALED [provider=tamash, suggested="By.id("username")"]` console line and a
`.tamash-selenium/heals.jsonl` entry with a real derived selector.

Needs a local Chrome (default; set `TAMASH_BROWSER=firefox|edge` otherwise). Selenium Manager
provisions the driver.

```sh
mvn test -Dtest=PageFactoryHealingTest -DHEALER_PROVIDER=tamash
```

Same, for the `@FindBy` / PageFactory path (`TamashPageFactory` → `TamashFieldDecorator` →
`LazyHealingElementHandler` → the healer, with the action name known). Watch for
`element.sendKeys "Username (textbox)" -> HEALED`.

```sh
mvn test -Dtest=WaitHealingTest -DHEALER_PROVIDER=tamash
```

A locator broken inside `WebDriverWait.until(...)` heals — the first few polls are deferred
(a still-loading page), then the heal fires and the wait succeeds; `HealCache` keeps the remaining
polls free. Also covers `FluentWait` and a `@FindBy` field polled inside `ExpectedConditions.visibilityOf`.

```sh
mvn test -Dtest=FrameworkIntegrationTest -DHEALER_PROVIDER=tamash
```

Drives the TestNG base class and the Cucumber hooks programmatically and asserts the heal is
attributed to the right test / scenario.

## 3. Real end-to-end — real browser, real AI provider

Required for anything touching provider request/response handling, vision, action recovery, or the
`ref`/widening path against a live DOM. Needs a valid provider key:

```sh
mvn exec:java -Dexec.args="doctor"          # confirm connectivity + the vision-capability label
mvn test -Dtest=SampleTest                  # a real heal against a live site
```

## 4. apply-heals round-trip

1. Run (2) or (3) so a heal is recorded.
2. `mvn exec:java -Dexec.args="apply-heals --dry-run"` — check the `By.…` rewrite preview.
3. `mvn exec:java -Dexec.args="apply-heals --yes"` — rewrites the `.java` source.
4. `sh .tamash-selenium/verify-heals.sh` — re-runs the affected test(s) with `HEALER_ENABLED=false`;
   a pass proves the rewritten selector stands alone.
5. `git diff` and revert (the point is to verify the mechanism, not keep the edit).

## 5. HTML step report

```sh
mvn test -Dtest=TamashRuleBasedHealingTest -DHEALER_PROVIDER=tamash -DTAMASH_REPORT=target/tamash-report.html
```

Open the file and confirm the healed step shows `healed via tamash — recovered as By.id("username")`.

## Gotchas

- The lifecycle pins Selenium's implicit wait to 0 so a broken `findElement` surfaces immediately.
  Healing runs on a direct `driver.findElement(broken)` **and** inside `WebDriverWait` /
  `FluentWait` (the first few polls are deferred as "still loading", then it heals).
- `apply-heals` can only rewrite an inline `By.x("…")` literal or `@FindBy` on the recorded line.
  A locator kept in a separate `private final By field = ...` is reported *skipped* — apply from
  `heals.jsonl`'s `newLocator` / `newFindBy` by hand.
- `.tamash-selenium/` is gitignored and accumulates `heals.jsonl` entries across runs — delete it
  between unrelated verification sessions.
- Config precedence is **OS env var → `-D` system property → `.env`**.
- `TAMASH_DEBUG=1` prints the DOM-snapshot capture length / failure to stderr.
